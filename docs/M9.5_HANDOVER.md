## 1. Why we're doing this

The user asked "what would be best suited and the gold standard way?" after seeing that
the inline loop was the actual runtime. Tradeoff table from the prior session:

| Framework | Verdict |
|-----------|---------|
| **Pydantic AI** | **Top pick.** Pydantic-native, free JSON Schema from type hints, native Ollama, OTel built-in. |
| **Pydantic Graph** | **Pipeline state machine.** The dump lifecycle is a graph. Type-safe transitions kill the `step_listener` race. |
| **Instructor** | **Structured output.** Replaces the hand-rolled `[ASK]`/`[FINALIZE]` regex parser. |
| smolagents, LangGraph, LangChain, CrewAI, AutoGen, Letta, OpenAI Agents SDK | Skip — see prior chat for full matrix. |
| Inline loop (current) | Survives as `_HAS_PYDANTIC_AI = False` fallback. |

Total new deps: **3 packages** (`pydantic-ai`, `pydantic-graph`, `instructor`).

## 7. Open risks

1. **Pydantic AI + Ollama compatibility.** Pydantic AI uses an OpenAI-compat shim for
   Ollama. qwen3-14b-agent may or may not handle tool calling well. The spike in Phase 1
   catches this. If the LLM ignores tool calls, fall back to the inline loop for the
   production path and document `pydantic_ai_known_good: false` in the config.
2. **Pydantic Graph SQLite persistence.** The library has `FileStatePersistence` but
   not SQLite out of the box. Agent 4 writes a ~30-LOC custom persistence that maps
   `DumpState.model_dump_json()` into the `dumps.metadata_json` column. No schema
   migration needed (column already exists from M2).
3. **Instructor retries and cost.** Each instructor retry is another LLM call. For the
   listener parser (called per turn), this is ~3x the LLM cost. The fallback regex
   parser is free. The agent should fall through to regex on the first validation
   failure to keep the dev experience fast.
4. **Test runtime.** 412 tests run in ~17s today. Adding ~30 new tests should keep
   total <25s. If it goes over 30s, suspect the LLM-touching tests — they should be
   mocked, not live.
